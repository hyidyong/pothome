# 연도별 공개 이력 타임라인 디자인 스펙

- 상태: 사용자 승인
- 적용 경로: `/resume`
- 기준: 사용자가 명시적으로 허용한 이력서의 연도·활동명·역할·업무 요약과 직접 작성한 포트폴리오
- 제외: 연락처, 주소, 생년월일, 사진, 성별, 계약·지원 원문, 제3자 인사정보, 원시 조사자료

## 1. 문제와 목표

기존 `/resume`은 `Strategy Research & Decision Design` 같은 네 개의 역량 묶음을 보여 주었다. 이는 실제 이력서가 아니라 포트폴리오 소개에 가까워, 연도별 경험과 역할을 확인하려는 채용 담당자의 질문에 답하지 못한다.

새 화면은 최신순 연도 타임라인으로 실제 경험을 보여 준다. 전략기획·HR·PM 역량은 별도의 주장으로 나열하지 않고, 각 활동의 역할·업무·산출물에서 읽히게 한다.

## 2. 정보 구조

1. 짧은 헤더: `공개 이력`과 전략기획·HR·PM 포지셔닝
2. 연도별 타임라인: 2026 → 2025 → 2024 → 2023 → 2022
3. 각 타임라인 항목: 기간(연도 또는 연월), 활동명, 조직명(공개 허용된 경우), 역할, 1~2문장 업무·산출물
4. `교육 및 수료` 보조 섹션: 이수 과정 전체 목록과 역할 기반 분류
5. `학력` 보조 섹션: 2022년부터의 법학 전공 재학 정보만 표시
6. 포트폴리오 CTA: 각 문서화 프로젝트를 `/work/[slug]`로 연결

## 5. 콘텐츠 표기 원칙

- 기간은 최신순이며, 복수 연도 경험은 종료 연도와 시작 연도 모두에서 중복 노출하지 않고 종료 연도 그룹에 한 번만 배치한다.
- 수상은 성과로 과장하지 않고 수상명·연도·역할만 표시한다.
- 포트폴리오 프로젝트는 `문서화`, `제안·프로토타입`, `독립 연구`, `미게재 연구 초안` 등 기존 근거 상태를 그대로 유지한다.
- 근거가 없는 고객사 수행, 매출, 채택, 장기 사용, 법률 자문은 추가하지 않는다.
- 공개 허용되지 않은 개인 연락처와 사진은 UI·DB·소스에 넣지 않는다.

## 6. 화면과 인터랙션

- 데스크톱: 왼쪽의 큰 연도와 오른쪽의 활동 카드가 대응하는 2열 타임라인
- 모바일: 연도 라벨 뒤에 활동 카드가 세로로 이어지는 1열 오토레이아웃
- 카드에는 활동 유형(`실무`, `프로젝트`, `대외활동`, `수상`, `교육`)을 텍스트와 아이콘으로 함께 표시한다.
- 기존 사이트의 reveal 시스템을 사용해 카드가 화면 진입 시 한 번만 `opacity`와 `transform`으로 나타난다.
- `prefers-reduced-motion`에서는 모든 카드가 즉시 보이며 타임라인은 정적 목록으로 동작한다.
- 연도·활동·조직·역할·설명은 `word-break: keep-all`과 균형 잡힌 제목 줄바꿈을 적용한다.

## 7. 데이터와 구현 경계

- 운영 데이터 원본은 로컬 Supabase의 `experience_entries`다.
- 현재 네 개의 일반화된 경험 행은 공개 이력에서 제거하고, 연도·기간·유형·조직·역할·요약·근거 상태·정렬 순서를 가진 타임라인 행으로 대체한다.
- 스키마가 필요한 필드를 지원하지 않으면 재현 가능한 SQL 마이그레이션으로 추가하며, 브라우저 저장소나 정적 데이터로 우회하지 않는다.
- 페이지는 서버에서 공개 데이터만 읽고, 외부 배포나 쓰기 인증은 추가하지 않는다.

## 8. 검증 기준

1. `/resume`에 일반화된 네 개의 이전 경험 문구가 남지 않는다.
2. 2026~2022 타임라인이 최신순으로 표시된다.
3. 사용자 제공 YLC·반기문 재단·교육 수료 정보가 누락되지 않는다.
4. 기간 불명확 프로젝트가 실제 수행 연도로 오인되지 않는다.
5. 모바일 390px, 데스크톱 1280px, 모션 감소 설정에서 가로 넘침·숨은 콘텐츠 없이 읽힌다.
6. DB·컴포넌트·페이지 테스트, 타입 검사, 린트, 빌드가 통과한다.
